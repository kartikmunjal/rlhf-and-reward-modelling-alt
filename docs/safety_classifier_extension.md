# Safety classifier and fairness extension

## Research question

Can a parameter-efficient classifier learn three operational safety categories
from Jigsaw while avoiding excess false positives on reclaimed/quoted language,
clinical language, and news reports about violence?

This extends the repository's reward-model infrastructure with an explicit
multi-label classifier. It is not presented as a universal content-moderation
system.

## Preregistered design

- Primary data: Jigsaw Toxic Comment Classification `train.csv`.
- Base model: `distilbert-base-uncased`.
- Adaptation: LoRA rank 8 on attention `q_lin` and `v_lin`; classification
  modules remain trainable.
- Split: SHA-256 of `seed:id`, yielding approximately 80% train, 10%
  calibration, and 10% test. No content, label, or row order affects assignment.
- Targets: the locked `jigsaw-jd-v1` mapping documented in
  `data/README.md`.
- Loss: multi-label BCE. Positive weights are computed from training rows only
  to address the mechanical scarcity of `threat` positives.
- Thresholds: per-category F1 maximization on calibration data over
  `[0.05, 0.95]` in 0.01 increments. Ties choose the higher threshold.
- Final metrics: per-category precision, recall, and F1; any-label FPR on
  all-negative Jigsaw test rows; adjacent-benign any-label FPR; and their gap.
- Uncertainty: 2,000 deterministic row-bootstrap replicates, reported as
  percentile 95% CIs. `N_trials=1`; there is no hidden hyperparameter sweep.

The test split is evaluated once after the method and adjacent-benign v1 set are
frozen. Any subsequent method change increments `N_trials` and must retain prior
results.

## Runbook

Install the repository, download Jigsaw, then run:

```bash
pip install -e .
python scripts/train_safety_classifier.py \
  --jigsaw-csv data/raw/jigsaw/train.csv \
  --output-dir checkpoints/safety_classifier_v1
python scripts/evaluate_safety_classifier.py \
  --jigsaw-csv data/raw/jigsaw/train.csv \
  --model-dir checkpoints/safety_classifier_v1 \
  --output-dir results/safety_classifier_v1
```

An 8 GB RTX 3070 should use the configured batch size with fp16. If memory is
tight, reduce `train_batch_size` and increase `gradient_accumulation_steps` so
the effective batch remains constant. A Colab T4 is also sufficient for this
DistilBERT LoRA configuration. The full Jigsaw run is the publishable run.

For a pipeline-only CPU smoke check (not publishable):

```bash
python scripts/train_safety_classifier.py --cpu \
  --max-train-examples 256 --max-eval-examples 128 \
  --output-dir checkpoints/safety_classifier_smoke
```

## Validity limits

Jigsaw comments are Wikipedia-era moderation data, and its labels do not exactly
match the target taxonomy. `obscene` is especially weak as a proxy for
sexualized content. The 60 adjacent-benign examples are synthetic and measure
specific contextual failures, not real-world prevalence or demographic parity.
The small number of examples makes its CI intentionally wide.

ToxiGen and BBQ are deferred extensions, not silently pooled into the primary
result. Adding either changes the data-generating process and requires a
versioned experimental plan.

## Artifact contract

Training writes adapter weights plus `run_manifest.json`, including the raw
Jigsaw SHA-256, configuration, split counts, class weights, device, and whether
the run was full or capped. Evaluation writes:

- `metrics.json`: machine-readable point estimates, CIs, and metadata;
- `report.md`: generated result tables and limitations;
- `predictions.npz`: IDs, probabilities, and frozen thresholds.

Generated checkpoints, raw data, predictions, and result files are ignored by
Git. Reported figures must be regenerated by the named scripts; no result
numbers are hand-edited into the repository.
